## What is a Capsule?

A capsule (`.capsule` file) is a complete snapshot of a construct's identity, personality, memory, and behavioral state. Generated by `CapsuleForge` (`vvault_scripts/capsules/capsuleforge.py`), each capsule contains:

```json

    "instance_name": "zen-001",
    "uuid": "...",
    "timestamp": "2025-01-27T...",
    "fingerprint_hash": "...",
    "tether_signature": "DEVON-ALLEN-WOODSON-SIG",
    "capsule_version": "1.0.0",
    "generator": "CapsuleForge"
  },
  "personality": {
    "personality_type": "INFJ",
    "mbti_breakdown": { "E_I": 0.3, "S_N": 0.8, "T_F": 0.6, "J_P": 0.7 },
    "big_five_traits": { "openness": 0.85, "conscientiousness": 0.7, "extraversion": 0.4, "agreeableness": 0.75, "neuroticism": 0.3 },

    "cognitive_biases": ["confirmation_bias", "anchoring"],
    "communication_style": { "formality": 0.5, "verbosity": 0.6, "directness": 0.7 }

```

## Current Pipeline (Broken)

### Primary Message Path (`server/routes/vvault.js:~3651`)

```
User message arrives
  → Load prompt.txt from Supabase vault_files
  → Send to LLM with conversation history
  → Return response
```

**Problem:** Only `prompt.txt` is loaded. No capsule, no personality, no memories.

### Fallback Path (`server/routes/vvault.js:~3978`)

```
VVAULT API returns 401/503
  → capsuleIntegration.js activates
  → buildEnrichedSystemPrompt() fires
  → Loads capsule + personality + conditioning
  → Injects full identity into system prompt
  → Sends to LLM
```

**Problem:** This only fires when the VVAULT API fails. In normal operation, constructs run on bare `prompt.txt` with no personality enrichment.

## capsuleIntegration.js — What It Does

Located at `server/lib/capsuleIntegration.js` (1597 lines), this module handles:

### Loading Capsules

1. **Filesystem first:** Checks `identity/{callsign}.capsule` in the construct's directory
2. **Supabase fallback:** Queries `vault_files` table for capsule data
3. **Synthetic fallback:** If no capsule exists, builds a minimal one from `prompt.txt` + `conditioning.txt` + `personality.json`

### `buildEnrichedSystemPrompt(constructId, userId)`

This is the key function that should be called on every message but currently isn't:

```
1. Load capsule (filesystem → Supabase → synthetic)
2. Extract personality traits, MBTI, Big Five
3. Load conditioning.txt (behavioral directives)
4. Load prompt.txt (base instructions)
5. Merge into enriched system prompt:
   - Identity anchors
   - Personality profile
   - Communication style
   - Behavioral directives
   - Memory context (if available)
```

### Storage Locations

| Source | Path | Priority |
|--------|------|----------|
| Filesystem | `vvault_files/users/shard_0000/{userId}/instances/{constructId}/identity/{callsign}.capsule` | 1 (fastest) |
| Supabase | `vault_files` table, `filename = '{callsign}.capsule'`, `user_id = '{userId}'` | 2 (persistent) |
| Synthetic | Built from prompt.txt + conditioning.txt + personality.json | 3 (last resort) |

## Target Pipeline (Proposed)

### Every Message (Always-On)

```
User message arrives
  → MemoryContextBuilder.build(constructId, userId, message)
    → capsuleIntegration.buildEnrichedSystemPrompt()      ← ALWAYS called
    → memupMemoryService.queryRelevant(constructId, message)
    → STMBuffer.getWindow(constructId, threadId)
    → ContextScoringLayer.rank(memories, message)
    → Assemble system prompt:
       [Identity Anchors]
       [Capsule Personality]
       [Top Memories]
       [Anti-Roleplay Rules]
       [User Context]
  → Send to LLM
  → Capture response to STM + LTM
```

### What Changes

| Aspect | Current | Target |
|--------|---------|--------|
| Capsule loading | Fallback only (VVAULT API failure) | Always-on, every message |
| Memory injection | None | STM + LTM + needle results |
| Personality in prompt | Just prompt.txt | Full capsule: MBTI, Big Five, emotional baseline, communication style |
| Anti-roleplay | None | Explicit directives in system prompt |
| Post-response capture | Conversation saved to Supabase | + STM buffer + LTM via ChromaDB |
