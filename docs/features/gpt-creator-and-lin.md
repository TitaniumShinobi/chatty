# GPT Creator and Lin

Archive doctrine:

Archive docs are archive-backed continuity evidence. When archive docs conflict with live code or newer summaries, classify the conflict as implementation drift, documentation compression, unwired design intent, superseded with evidence, or needs Devon reconciliation. Do not dismiss archive docs as non-authoritative merely because they are archived.

## Product Contract

- Lin is the local-first orchestration substrate for GPTs in Chatty.
- GPT Creator Create tab may speak as Lin while helping Devon shape a GPT.
- GPT Creator Preview and normal runtime must speak as the target construct, not Lin.
- `/api/vvault/message` is the construct-quality conversation path for both Preview and main chat.
- `/api/lin/generate` is helper/tool-only for Lin assistance and seat experiments.
- Provider/model choices are routing settings. They do not rename, absorb, or recondition the selected construct identity.

## Implementation Expectations

- Lin defaults come from `config/linModelDefaults.json`, with server and client wrappers proving parity.
- Create-tab save payloads should preserve local Lin defaults unless Devon explicitly selects provider/model overrides.
- Switching to Lin mode must not silently write OpenRouter defaults.
- Saved Lin configs with stale OpenAI/OpenRouter fields must normalize to the shared Lin defaults before preview, save, or create payloads.
- Custom Models mode is where explicit OpenAI, OpenRouter, or alternate Ollama route choices are preserved.
- Sim mode preserves the selected construct's local model artifact lock.
- Construct-facing prompts must not list all model seats as identity text. Seat/provider details belong in runtime receipts, checklists, UI diagnostics, and tests.
- Manual `ollama:`, `openrouter:`, or `openai:` overrides in Custom Models mode may change routing only; they must not change the construct name, voice, memory scope, or instructions.
