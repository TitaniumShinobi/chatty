Here's what I did to fix the knowledge file upload issue:

The problem: There was no upload endpoint for knowledge files, and no file size limit was configured — so uploading a 200MB+ zip was either failing silently or choking because files were being sent one at a time from the client.

What I built:

Set the max upload size to 500MB — so your large zip files won't get rejected by the server.

New bulk upload endpoint (POST /api/vault/knowledge-files/upload) — This accepts your zip file directly. The server:

Extracts the zip on its end (no need for the client to unpack 222 files individually)
Routes each file to the correct VSI folder automatically (documents, identity, config, etc.)
Handles PDFs and images as binary (base64 encoded)
Upserts — if a file already exists, it updates it instead of duplicating
Computes SHA-256 from the original file bytes for integrity
Skips hidden files (.DS_Store etc.) and files over 50MB individually
Returns a summary of what was created/updated/failed
Delete endpoint (DELETE /api/vault/knowledge-files/<file_id>) — so you can remove individual knowledge files, scoped to your user account only.

The Chatty frontend will need to call this new endpoint (/api/vault/knowledge-files/upload) with the zip file instead of uploading files one by one. You should be able to send the whole zip in one request now.
