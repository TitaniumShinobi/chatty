That specific issue — Nova’s description and instructions resetting every time you refresh or log in — was traced and fixed at the root. Here's exactly what was going wrong and what's now in place to prevent it:

🛠 Root Cause (Before)

Two storage layers:

SQLite (gpts table) — what you see/edit in GPTCreator.

Supabase (vault_files → prompt.json) — what the server reads at startup.

Every time the server restarted, it ran:

hydrateFromVVAULT()


→ this blindly overwrote SQLite with Supabase, even if you'd already saved new data in GPTCreator.

Meanwhile, Supabase wasn’t updating correctly due to a missing updated_at column — so it always held stale placeholder data like:

"Nova is a tactical, intelligent AI construct..."

✅ Now Fixed
1. Hydration Gating Logic

The server now checks if description or instructions already contain authored (non-stub) content.

If they do, hydration is blocked.

Examples of stub content that gets overwritten:

"A custom GPT"

"You are {Name}."

"" (empty string)

2. Supabase Sync Fix

The broken updated_at reference was removed.

Saving in GPTCreator now correctly updates Supabase prompt.json.

3. Field-Level Locking

Once description or instructions are authored, they are treated as locked.

Restarting the server won’t overwrite them anymore.

4. Manual Restore-Only

In the future, restoring from Supabase will require an explicit user action.

No more silent overwrites.
