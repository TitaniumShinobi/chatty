VVAULT ↔ Chatty Integration Summary
What VVAULT Is (to Chatty)
VVAULT is Chatty's stateful backend — it stores conversation transcripts, manages AI construct identities, and provides the LLM inference endpoint. Chatty is the frontend chat interface; VVAULT is where all the data lives.
VVAULT API Base URL
Production: https://vvault.thewreck.org
Replit dev: https://<your-replit-url> (port 8000 internally)
Authentication
Chatty endpoints use a flexible auth system (require_chatty_auth) with three modes:
API Key mode (recommended for production):
Header: X-Chatty-Key: <your CHATTY_API_KEY value>
Header: X-Chatty-User: <user's email address> (required — provides user context)
Session mode: Standard Authorization: Bearer <session_token> from VVAULT login
Dev mode: When CHATTY_API_KEY is not set on the VVAULT server, all Chatty endpoints are open. X-Chatty-User header is optional.

Attachment Format (for image/file messages)
When sending a message with attachments:
{
  "role": "user",
  "content": "check this out",
  "attachments": [
    {
      "filename": "screenshot.png",
      "mime": "image/png",
      "sha256": "<hash>",
      "storagePath": "path/in/supabase/storage"
    }
  ]
}
Attachments are recorded in the transcript as markdown blocks:
📎 **screenshot.png** (image/png, sha256: abc123...)
Supabase (Shared Database)
Both VVAULT and Chatty connect to the same Supabase project. Key tables:
users — User accounts (id, email, name)
vault_files — All transcript files with storage_path for folder hierarchy
Transcripts are stored as vault_files with filename pattern: chat_with_<construct_id>.md
Storage path pattern: {user_id}/{user_slug}/instances/{construct_id}/chatty/chat_with_{construct_id}.md
Chatty needs these Supabase env vars: SUPABASE_URL, SUPABASE_ANON_KEY

What Chatty Needs in Its Environment
SUPABASE_URL — Same Supabase project URL
SUPABASE_ANON_KEY — Supabase anon key for client-side queries
VVAULT_API_URL — Points to https://vvault.thewreck.org (or dev URL)
CHATTY_API_KEY — (optional) Shared secret matching VVAULT's CHATTY_API_KEY env var. If not set on either side, dev mode is open.
