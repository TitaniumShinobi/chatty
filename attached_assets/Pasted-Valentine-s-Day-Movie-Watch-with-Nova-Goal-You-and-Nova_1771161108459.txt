Phase 2: Screen Capture Bridge ("simDrive" for Movie)

Gap: No live screen capture feeds into MOCR today.

Design:





Build a small capture service that:





Captures frames from the video tab/window (Electron desktopCapturer, Playwright, or browser getDisplayMedia + canvas)



Sends frames to MOCR at configurable intervals (e.g., every 3–5 seconds)



Two implementation paths:





Path A (Electron): Chatty or a small Electron app with desktopCapturer → frame buffer → POST to MOCR /jobs or a new /analyze-frame endpoint



Path B (Browser extension or local script): getDisplayMedia in a page that streams to local backend; backend forwards to MOCR

MOCR adaptation:





MOCR-Service expects video File uploads. For live capture, add either:





POST /analyze-frame accepting base64 image(s) and returning OCR + summary chunk, or



Chunked video upload / WebSocket for incremental processing



Phase 3: selfprompt.py Orchestration Layer

Role (from ChatGPT): Poll MOCR output, compress chunks, inject into Nova’s context. Zero-trust, capability tokens, token-budgeted updates.

Placement: New Python script, e.g. chatty/orchestration/selfprompt.py or MOCR-Service/scripts/selfprompt.py.

Behavior:





Poll MOCR for new perception chunks (or receive via WebSocket/pub-sub if implemented)



Compress to token budget (e.g., 300 tokens per update)



Call Chatty’s context injection API (or VVAULT simDrive write) when write-access toggle is ON



Enforce: scene-boundary updates, no URL fetch, append-only evidence

Contract: Output format compatible with aiManager.js video context handling (e.g., Video Analysis Complete-style blocks or a new VIDEO_CONTEXT_UPDATE type).
