PHASE 1 — Tool Transparency
=============================
Implement runtime-truth `tool_trace` on every assistant turn.

Schema:
tool_trace: [
  {
    tool: string,          // e.g. web_search, ocr_image, screen_capture
    provider: string,      // e.g. duckduckgo, local_ocr, mocr
    input: string,         // compact summary/query
    ts: string,            // ISO time
    success: boolean,
    result_ref?: string
  }
]

Requirements:
1) `tool_trace` is attached to every assistant message.
   - No tools run => `tool_trace: []`
2) `tool_trace` must come only from actual runtime tool events.
3) UI: show “Tools used” pill per assistant message:
   - None | Search | OCR | Capture | Multiple
   - Click/expand shows raw trace.
4) Prompt rule (global/system):
   - If `tool_trace` is empty, assistant must not claim tool usage.
   - If non-empty, assistant should acknowledge tool use when relevant.

Acceptance checks:
- Normal “hello” with no tools => `tool_trace=[]`, pill = None.
- Run a real tool call => `tool_trace` populated, pill matches.
- Assistant text cannot claim search when trace is empty.
